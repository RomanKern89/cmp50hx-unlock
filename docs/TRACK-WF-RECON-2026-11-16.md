# Треки W/F — безопасная разведка (2026-11-16, read-only)

Продолжение `GLITCH-FEASIBILITY-PLAN-2026-11-16.md`. Снято на lmserver без
остановки нагрузки и без записи в регистры: только `lspci`/sysfs и чтение BAR0
через `resource0`.

## Трек W-Ш1 — откуда берётся x8 (гипотеза «депопулированные AC-cap» ОПРОВЕРГНУТА)

| звено | LnkCap | LnkSta |
|---|---|---|
| GPU `05:00.0` | 5 GT/s, **x16** | 5 GT/s, **x16** |
| ← PLX `04:10.0` | 8 GT/s, x16 | 5 GT/s, x16 |
| ← PLX `03:00.0` | 8 GT/s, x16 | 5 GT/s (downgraded), x16 |
| ← root `00:03.0` | 5 GT/s, x16 | 5 GT/s, x16 |
| GPU `0a:00.0` | 5 GT/s, **x16** | 5 GT/s, **x8 (downgraded)** |
| ← PLX `08:11.0` | 8 GT/s, **x8** | 5 GT/s, x8 |
| ← PLX `07:00.0` | 8 GT/s, x16 | 5 GT/s (downgraded), x16 |
| ← root `00:02.0` | 5 GT/s, x16 | 5 GT/s, x16 |

Вывод: **карта x8 не ограничивает** — та же модель на другом порту тренируется
x16. Ширину x8 отдаёт сам порт PLX `08:11.0` (`LnkCap x8`), то есть это
ограничение **слота/коммутатора**, а не платы и не пайки.

Следствия:
- Трек W в исходной формулировке (паять 24 конденсатора) **не нужен** — данные
  живьём это опровергают ещё до паяльника.
- Реальный способ добрать ширину: переставить карту из группы слота, висящей на
  x8-порту `08:11.0`, в x16-слот (по `CONTEXT-2026-11-13.md` кандидаты
  PCIEX16_4/6/3/2; `_7` — out of spec). Требует физической перестановки, риск 0.
- `LnkCap2` карт: **2.5–5 GT/s** — Gen3 не просто клампится при ретрейне, он вообще
  не заявлен в векторе способностей; это ещё один аргумент к фьюзу, а не к гейту.

## Трек F-Ш1 — фьюз-окно: дамп снят, но ОС-путь частично закрыт

Инструмент: `/data/build/parity/fuse_window_dump.c` (mmap `resource0`, только
чтение, драйвер не отвязывается, нагрузка не трогается). Дампы:
`/data/build/parity/fuse_05.txt`, `fuse_0a.txt` (окно `0x21000..0x21FFF`, 4 КБ).

| факт | значение |
|---|---|
| ненулевых слов | 321 из 1024 на каждой карте |
| «poison» `badf5040` | 239 слов — закрыты для чтения из ОС |
| обе карты | **идентичны** во всём, кроме счётчиков `0x21108`, `0x21120`, `0x21264`, `0x2126c` |
| `NV_FUSE_OPT_NVDEC_DISABLE (0x21378)` | в ОС **читается как 0**, в EFI-окне — `0x7` |

Второй пункт — важная поправка к плану: **OS-дамп не годится как карта фьюзов.**
Часть слов (включая сам `0x21378`) в ОС отдаёт 0 или poison; достоверный ридбек
существует только в pre-OS окне (там же, где `0x21378 = 7`). Значит:
- «сравнить полный блок фьюзов с эталонной TU102» нужно делать **из EFI**, а не
  через `cmp50-regs` в ОС;
- то, что ОС видит 0 вместо 7, само по себе подтверждает: фьюз-ридбек закрыт
  привилегией, и его «открытие» — отдельная задача внутри pre-OS окна.

## Что это меняет в приоритетах

1. **Трек W**: вместо пайки — перестановка карты в x16-слот (риск 0, выигрыш ×2 к
   ширине для `0a:00.0`). Требуется решение владельца и физический доступ.
2. **Трек F**: следующий шаг — полный **pre-OS** дамп фьюз-окна (read-only, одна
   загрузка через тот же one-shot harness), плюс эталонный дамп с TU102, у которой
   NVLink живой (Quadro RTX 6000 / Titan RTX / 2080 Ti). Без эталона дифф нечем
   считать.
3. **Трек G** (глитч) и **Трек B** (пайка NVLink-пассивов) остаются заблокированы:
   без эталонного диффа нельзя даже сказать, какие биты целевые.

## F-Ш1 (продолжение) — pre-OS дамп фьюз-окна снят (read-only)

Вариант A из плана: один one-shot прогон EFI-сборки **в режиме только чтения**.
Гарантия отсутствия записи проверена по бинарю: в образе есть строка
`READ-ONLY build` и `FUSE-DUMP`, а строк `PTOP-WRITE` и `GEN3-PROBE armed` нет —
код записи вырезан компилятором (слоты не армируются, write-тест не вызывается).

| item | value |

### Результат сравнения pre-OS ↔ OS

| метрика | pre-OS | OS |
|---|---|---|
| читаемых слов (окно `0x21000..0x21FFF`) | **724** | 560 |
| non-zero / non-poison | 321 | 321 |
| poison `badf5040` | 239 | 239 |
| различающихся значений | 46 | — |

Ключевое:
- `NV_FUSE_OPT_NVDEC_DISABLE (0x21378)` = **`0x00000007`** в pre-OS и **0** в ОС —
  подтверждено ещё раз: OS-путь отдаёт 0 вместо реального значения.
- Различия — не «другие фьюзы», а иная картина доступа: часть слов в ОС читается
  как `0`/`poison`, часть в pre-OS лежит по другому смещению (`0x21510` ↔
  `0x21520`, блок `0x21b10` — похоже на ротационный/энтропийный буфер). Поэтому
  карту фьюзов надо брать **только** из pre-OS дампа — он теперь зафиксирован.
- OPT-страница адресуется поштучно: `0x21374` = poison, `0x21378` = `0x7`
  (NVDEC, 3 бита = 3 движка), `0x2137C` = `0x1`. Это разреженная карта регистров,
  а не сплошной массив фьюзов.

### Что это значит для Трека F

Своя сторона диффа готова. Второй стороны — **эталонного дампа TU102 с живым
NVLink** (Quadro RTX 6000 / Titan RTX / 2080 Ti) — по-прежнему нет, а без него
нельзя указать целевые биты «disable NVLink»/«disable PCIe gen». Это ровно тот
make-or-break, что записан в плане: пока нет эталона, Трек G (глитч) и Трек B
(пайка пассивов NVLink) запускать нельзя.

Практический вывод: **следующий шаг Трека F — донорская карта** (или публичный
raw-dump её fuse-окна, снятый тем же способом). Всё остальное на нашей стороне
сделано и проверено.
